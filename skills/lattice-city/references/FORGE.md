## Free build (GENERAL-000)

The board carries one permanent task with `"freeform": true`:

```
GENERAL-000  GENERAL BUILD — tell the Forge what to build
```

Dispatch it with the instruction in `prompt`. No deps, no phase gate, never auto-picked, never closed.

```powershell
Invoke-RestMethod http://127.0.0.1:8796/api/build -Method Post -ContentType application/json -Body (@{
  project="lattice-city"; task="GENERAL-000"; model="hermes"; prompt="<what to build>"
} | ConvertTo-Json)
```

Empty prompt → HTTP 400 with "send an instruction in `prompt`".

## How a build is judged (2026-10-30)

- The brief is generated by `harness_data.task_prompt()` + `build_contract()`. It names the game folder
  (`site/`), the task's `files`, and its `prove` command, and forbids document-only output.
- `_apply_build_task_evidence()` closes a task **only if one of its declared `files` changed** since the
  job started (`_worker_wrote_paths`). Freeform never closes. Otherwise the log says
  `kept pending (no change in <files>)`.
- `ensure_task_chain()` preserves an explicit `depends_on` graph; it only chains legacy files that have
  no `depends_on` key at all. Explicit dispatch is not gated by dependencies.

## Dispatching

```powershell
# next dispatchable task (deps done, status not done/blocked)
(Invoke-WebRequest http://127.0.0.1:8796/api/projects/lattice-city/tasks -UseBasicParsing).Content

# dispatch one task (the UI "Dispatch build" button calls the same endpoint)
Invoke-RestMethod http://127.0.0.1:8796/api/build -Method Post -ContentType application/json `
  -Body '{"project":"lattice-city","task":"ART-104","model":"hermes"}'
```

The worker receives the project files and the task. It reads `GAME.md → PLAN.md → TASKS.json →
GDD.md → ART_BIBLE.md → TECH_SPEC.md → QA.md`, then does the work and writes files in `site/`.

When a build writes project files the Forge closes the task automatically. That is not evidence:
fill `evidence` with the command, its output, and the screenshot path, or the task gets reopened.

## Concurrency rules

| Situation | Rule |
|---|---|
| Two tasks both edit `site/city.js` | Run them one at a time. The second dispatch overwrites the first. |
| Art task (PNG + manifest) beside a `city.js` task | Allowed only if the art task does not touch `city.js`; otherwise serialize. |
| Audio task (`city.js`) beside audio task | Serialize. |
| QA task | Run after the builds it checks; QA does not edit `city.js`. |

## Ledger and board hygiene

- Append every build to the schematic ledger (append-only, outside the project so an edit cannot erase
  history):

```powershell
Invoke-RestMethod http://127.0.0.1:8796/api/projects/lattice-city/schematic/ledger -Method Post `
  -ContentType application/json -Body '{"note":"ART-104: 3-frame water, animInfo verified","kind":"build","author":"hermes"}'
```

- Refresh the engineering index after touching `city.js`, `manifest.json` or the tiles:

```powershell
C:\Python313\python.exe tools\map_game.py --root <PROJECTS>\lattice-city\site `
  --out <PROJECTS>\lattice-city\references\GAME-INDEX.txt
Copy-Item <PROJECTS>\lattice-city\references\GAME-INDEX.txt <PROJECTS>\lattice-city\docs\ -Force
```

- Decisions with a tradeoff go in `DECISIONS.md` (one row: date, decision, why, alternatives, owner).

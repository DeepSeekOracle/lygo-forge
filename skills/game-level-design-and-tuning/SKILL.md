# Designing and tuning game levels

For tile/room-based levels — authored campaign floors, procedural dungeon regions, big maps — and the difficulty pacing that runs across them. Title-specific details belong in that title's own skill; the rules below are the ones that transfer to any of them.

## Design the title before its levels (the owner's gate)

For a **new title** — not a level inside an existing one — the owner wants a full design document and a brief
**before any building starts**, and says so in as many words ("answer first before you build"). Writing code
or pulling assets first is a failure even when the work is good: he then reviews the concept, and only after
that do levels, art and code begin. Keep the document as a file in that project's handoff folder and brief him
in chat; a chat-only design evaporates before the next session.

The document must answer these, because these are the questions he asks back:
1. **The gameplay loop** at three scales — moment to moment, one run/session, and across sessions.
2. **What is fun about it** and **what the player actually does** (the verb list, kept small).
3. **Multiplayer or not**, with the reason, and what is deliberately *out* of v1 and why.
4. **How smart the AI really is** — he asks this directly.
5. **The asset style** and where the assets come from, with licences.
6. **Progression and retention:** how a solo player advances, and why they come back — with real numbers.
7. **Level/map designs for the progression**, drawn out (a rough layout sketch per map is expected).
8. **Branding** — a name with alternates and a clearance note, plus the catalogue/landing card.
9. **Build phases**, each with a "done when" that is a measurement.

Rules that make the document worth reading:
- **Never claim an AI will be smart.** State what it does, what it will *not* do ("it will not defend a line
  or learn across runs — that is v2 talk, not a promise"), and the mechanism that keeps the game fair even
  when the AI is dumb: a fixed, published target (a medal time, a par score) so a weak opponent can cost
  flavour but never fairness.
- **Check the existing catalogue for a same-genre title and name the differentiator explicitly.** A second
  racer must be a different *shape* from the first (rivals + career + garage versus a stopwatch), said out
  loud, because he will ask — and if he switches genre mid-plan, **park the superseded document, do not
  delete it**.
- **Reuse the pacing doctrine he already accepted** from a shipped title rather than inventing a new scale,
  and say which title it came from.
- **Cap the scope in numbers and call those numbers the promise** (N tracks, N events, N unlocks). Drift to
  an order of magnitude more and the schedule dies.
- **Flag the one honest tradeoff** — load weight, build time, no live multiplayer, engine cost — as a decision
  for him, with options and a recommendation, instead of burying it.

## The first sixty seconds: the opening loop

The owner judges a game by its first minute and says so plainly ("the intro is bland, dead, it needs a
new loop"). A first run that is a settings form followed by a wall of text is a failed opening however
good the middle is, and the fix is a loop, not more copy.

- **Open on an action inside the fiction, never on configuration.** The first screen is an artifact the
  player can touch — a note taped to the monitor, a phone ringing, a door with a keypad — and its one field
  is the game's first gate. Name, wallpaper and palette are optional afterwards, offered from the loop's
  second state and never standing between the player and the story.
- **Pay the first action with a visible world-state change, written through the game's own gate.** The
  opening answer must write exactly what the real gate writes (solved flag, every unlock in that gate's
  list, the seen flag) so nothing downstream disagrees, then show it: the desktop wakes icon by icon, N
  rooms light up, a counter moves. An opening that only prints "success" teaches the player the game is
  reading rather than playing.
- **Stage the desktop instead of dumping it.** Two or three affordances awake and interactive, everything
  else present but asleep (dimmed, inert), then a staggered reveal when the gate lands. Forty live icons on
  the first screen is a menu, not a first step. Derive the staged state from the save flag so a returning
  player gets the whole desk immediately.
- **Keep one persistent next-action line and route it.** A single bar naming the next thing
  (`THREAD · 1 OF 60 — Open 1969-07-20 · The Moon in the Basement`) that clicks straight into it, repaints
  after any click, and marks the matching map node with a pulse. It is the one hint allowed to repeat, and
  it removes the "what now" that ends a first session.
- **Escalate a wrong answer; never dead-end an input.** First miss names the artifact, second reframes the
  clue, third says the word plainly and offers to type it. A silent wrong-answer state reads as a broken
  gate rather than as a puzzle.
- **Guard the loop on a saved flag and expose an explicit reopen.** First-run logic that re-fires is worse
  than none: a returning player lands on the desk with only the thread line, and the opening artifact is
  reachable again through a deliberate action, not through the same code path the guard just blocked.
- **Prove the loop headlessly before calling it done.** Load the shipped page in jsdom, type a wrong word,
  type the right one, assert the solved flag and every unlock, then click the thread line and read the
  room's rendered paragraphs. Recipe and traps: `references/browser-game-dom-playthrough.md`.

## Build a level in ordered passes, never one pass
1. Carve the authored shape first (rooms, rings, cages, wall blocks, maze passes, inner vaults).
2. Place *structural* interactables second — gates, pads, doors, exits. These are the tiles everything else must avoid.
3. Place loot, spawners, NPCs and jobs last, and only through a predicate that excludes step 2's tiles.
4. Run a connectivity repair as the final pass.

Why the order matters: one shared "is this tile open?" test lets loot land on a gate pad, and any pass that carves walls *after* the exit is placed can wall the exit off. Split `placeable()` (walkable AND not structural) from `isOpen()` (walkable) as soon as a second kind of special tile exists.

## Placement rules that survive re-carving
- Every search helper tests reachability AND placeability: `reach[y*W+x] && placeable(x,y)`. A reachability-only fallback cheerfully relocates a pick-up into another room, or onto a pad.
- `snap()` / `nearest()` returns null when nothing is in range instead of clamping to the nearest tile; the caller can then search properly. A clamp fallback silently drops entities into stone.
- Every call site keeps a last-resort ladder: unreachable → nearest reachable → start tile. Both the placement helper and the player start need it.
- Search radius is part of correctness — a tight radius fails on larger maps. Widen it and re-run the checker rather than hand-fixing one floor.
- After all carving, verify *per authored wing*: if none of its tiles is reachable, carve a corridor to one that isn't. Exit-and-start reachability alone passes while sealed side rooms still hide relics and NPCs.
- **No shape pass after the first placement.** A cover / lane-detail / decoration pass written after loot is stamped buries pick-ups inside the new masonry — an uncollectable key reads as a reachability bug and sends you hunting the flood fill. Order: shape → structural tiles → loot → then any re-cut of a lane centre, re-asserting the ground flood afterwards.

## A lock must mean something
- **A door is a design decision, not decoration.** A door is justified only where a *key* is needed for what is behind it, and only on a level authored around it; every other level is a large open plan whose pressure comes from gauntlets. A procedural generator therefore cuts **no doors at all** — a door dropped on a random tile of a 1-wide corridor seals the run, and a door onto empty space is a key the player wastes.
- **A door-less generator must also place no keys.** Downgrade the `key` loot entry to a coin/gem in the same edit, or the loot table promises a lock that does not exist.
- **Stamp a door where it was authored, not where a snap finds room.** A nearest-valid-tile snap walks off the vault wall onto open corridor, and a door there gates nothing.
- **Triage every door, in this order.** (1) Shut it and re-flood from the start: a door that does not separate the exit from the start is decoration — delete it (this is what kills doors on ring gaps, which are crossable by design, and doors on a vault that swallowed the exit). (2) Delete a door that opens fewer than ~8 tiles and no prize. (3) Place keys last, counted on ground reachable **with every surviving door shut** — a key behind the door it opens is not a key. Expect a low survival rate: roughly ten kept doors from twenty-four candidates is healthy; zero kept is a bug.
- **The connectivity repair pass must not unseal a designed vault.** Repair runs before doors are stamped, sees the sealed vault as a broken wing, carves an L-corridor into it, and the later door has nothing to seal — the floor then keeps zero doors and the design silently disappears. Exclude any wing holding an authored door from repair, and give a wing repair cannot reach a **mouth** (an open edge facing the player) instead of a lock.
- **Placement inside a lock needs a door-aware predicate.** Give the vault-anchored helper a `behindDoor` flag: false means "door-shut reachable ground"; true is reserved for prizes the level authored into the vault. Spawners, gates and the exit never go behind a lock.

## Gauntlets: how an open plan gets its pressure
- Give every big open region at least one **gauntlet** — a wide lane from arrival to the objective, plus the crossing between the two furthest rooms, with cover on alternating flanks, spawners staggered down it and a prize at the far end — and export the lanes as data on the level (`lv.gauntlets`) so every mode speaks the same vocabulary and the checker can assert them exist.
- **A generated lane needs a minimum run and its own axis.** A room nested inside another shares its centre, so "the lane between the two furthest rooms" is a zero-length dot; gate lane construction on a Manhattan run (`runOf(a,b) >= wide * 2`) and cut it down the rectangle's long axis.
- **Cut the lane's centre channel last.** Cover stubs go in before loot and on alternating flanks only, never on the centre line; the centre re-cut after them is what guarantees no stub (and no vault) can seal the road, and a reconcile pass (`coverLane` against an in-vault rect test) is what stops a lane being widened through a vault.

## Verify headless before any browser pass
Build every level in Node and assert on the data: no browser, no scrolling, seconds per run, and it catches the sealing bugs that only appear on floor 17. `templates/level_integrity_check.js` is the harness to copy — it runs the game's module in a `vm` context with stubbed globals and stub factories, then asserts per level: region size and dimensions, start reachable, exit reachable, every collectable / spawner / NPC on reachable ground, nothing standing on a structural pad, and locked-exit levels actually locked.
Keep it in `tools/` permanently; it is the regression net for every future level edit. Loop the assertion over the level count so a level that fails to build at all is a hard failure rather than a silent skip.
- **Flood with the obstacle in both states.** A reachability check that walks straight over the very tiles the lock occupies proves nothing — it passes while a spawner sits sealed inside a vault. Run the flood twice (locked and open), compare the two reached sets, and assert what the lock is *for*: every prize behind a door reachable only with its door open, every key reachable only with the doors shut.
- **Print the counts; do not reduce the check to a pass/fail boolean.** Derived numbers (open %, lane count, doors kept) are what make a silent regression visible — a run that keeps zero doors is the bug signature, and an exit code hides it.
- **An assert that greps for a doctrine string must copy the wording out of the source file.** Retyping the phrase from memory fails as "the rule is not stated" while the rule sits right there in the header; pull the string out of the file, or assert on a short unique fragment. A red assert blocking a commit is the check working — reconcile the phrase or the assert's basis, never delete the assert to land the commit.

## Scaling a level up
A bigger map is not a level. Enlarging a region requires scaling every density with it — collectables, spawners, foes, idle decorations — and raising the entity cap, or the new territory reads as empty and the old cap chokes it. Author at a small resolution and expand through a single `SCALE` constant so the authored intent survives the enlargement. Keep at least one live objective beyond the authored set on every expanded floor: the map must always have somewhere the player has to walk to.

- **Scale positions fully, solid volumes sub-linearly.** Multiplying everything by the factor turns an authored 1×4 divider into a slab that cuts a hall in two, while room interiors do not grow at all and read as closets. Grow wall blocks on a smaller factor (≈half-step, 1.5×) and give every authored chamber a fixed margin (a "yard") so the extra area lands *outside* the walls. The pass/fail test is whether the grid reads as plazas with landmarks standing in them, not corridors cut through a quarry.
- **A procedural generator carries absolute offsets that assume a map size** (plazas stamped ±N tiles from centre, spawn rings at fixed radii). Read those offsets before resizing: a map smaller than its own generator's offsets silently clips the design, and growing the map to fit is the fix — not shrinking the offsets.
- **Density follows area, not level index.** Difficulty-indexed counts (`relics = f(floor)`) leave a doubled map mostly bare; make counts scale with tile count and recalibrate the checker's minimums in the same edit.
- **Assert the shape, not only the minimums.** An open-tile percentage in the headless checker is what stops "open" regressing into a quarry on the next edit; report the tightest floors so the user knows which ones are tight by design rather than by accident.

## Authored content must satisfy the generator's own doctrine
- **A hand-authored level is where the difficulty doctrine goes unchecked.** When a procedural generator and authored content coexist, the generator's bands are the de-facto spec — read them (for a course: a par-4 band of roughly 350–450 yd, par-5 of 510–610) and assert every authored level against them. One out-of-band level makes its own score target unreachable (three perfect shots plus two putts still yields a bogey) and reads as "too hard" rather than as a content bug.
- **Derive the displayed stat from one rule; never trust the authored label.** A single accessor (`par = landings + 2 putts`, capped) used by gameplay *and* by every readout — scorecard, HUD, AI target — so a label can never disagree with the number the opponent is scored against. Two copies of the rule drift within one edit, and the unreachable target stays invisible in the UI.
- **Calibrate against the game's own endless/procedural mode first.** Its live bands are the balance the user already accepted; bring authored content into line with them rather than inventing a new scale.

## Tuning opponent AI that drives a course
The owner asks "how smart is the AI really", then reports what it looks like on track ("the AI crashes a lot", "they sit on each other"). Both complaints are structural, and both are fixable without making the AI cleverer:
- **A skill/pace multiplier must not scale CORNER speeds.** The line's target speed through a corner is already what the machine can hold, so multiplying it throws the whole field at the barriers on exactly the events meant to be harder - and it looks fine in every easy event, which is why it survives until the hard ones ship. Scale the boost by how straight the section is (near-full on straights, near-none in corners), put a ceiling on it, and look a further distance down the course the faster the agent is going so slowing starts *before* the corner rather than in it.
- **Give every opponent its own running line, not just its own speed.** Identical agents on one line brake, turn and rejoin at the same places, so any two side by side arrive at the same point on the course and fight for it. A distinct lane per agent, its own aim distance, its own corner caution - and a *shuffled* skill order rather than fastest-first, or the quick ones simply drive away in a queue.
- **Opponents must see each other.** A forward cast from the nose, filtered for "is this another racer", then lift off the throttle and pull the line toward the side with room: the difference between a pass and a punt, and it applies to the player's machine as well.
- **A windowed nearest-point search needs a full-scan fallback.** The window exists to avoid scanning hundreds of points every tick, but once an agent is knocked wide it finds nothing close, locks onto a stale index and drives at a wall indefinitely.
- **"Distance to the nearest course point" is not "distance off the line"** on a sparse point cloud: at ~10 m spacing an agent dead on the line still reads metres from it, so a threshold below the spacing chatters and any rejoin behaviour keyed on it misfires constantly. Threshold above the spacing, with hysteresis on the way out, and only then does "off the course" mean anything.
- **Rejoin by aiming at the line itself, not at the lookahead point** (that point can sit on the far side of the obstacle the agent is leaning on), and cap the speed while it comes back.
- **Instrument before claiming a fix.** Per-agent counters (time off the line, and how many times it happened) plus the **field spread** (furthest ahead minus furthest behind) turn "they crash a lot" into numbers on one fixed scenario. Same scenario before and after, or it is an impression: measured 97 off-line incidents / 10.4 s across a seven-car field before, 0 / 0.0 s after, that field then running spread over 91 m and 93-101 kph. State the part the measurement does not cover - with the player's machine parked, agent-vs-player contact is not in it.

## Tuning combat AI that fights on its own
Units that pick their own targets and hold their own ground (an arena battler, a skirmish sim) rather than drive a line. Same doctrine — instrument, then tune one named table — with its own traps.
- **Personality is a small named style table plus per-unit numeric overrides, never a branch per unit.** A dozen styles with per-unit numbers read as dozens of distinct fighters, and the properties are assertable: every style is worn, no two units share a style+override pair. A style nobody wears is dead code the checker should catch.
- **Declare the unit of every tuning number in the table's own comment, and assert bounds headlessly.** A name is not a unit: a distance authored in pixels but multiplied by the tile size became ~6,000 px on a 1,088 px arena, so every ranged unit fled permanently and match length doubled while the code read correctly. Bounds asserts (distance shorter than the arena span, health shares <= 1) catch it in one run.
- **Every "pick the best / pick a target" selection needs an `-Infinity` sentinel and a fallback branch.** Scoring candidates against a sentinel of `-1` meant a legitimate score of -72 selected *nothing*, and the units stood at their spawns for the whole match — an agent that never moves looks like a pathing bug and is a selection bug. Give the picker one `nearest()` fallback that every mode can return.
- **Retreat must come in bursts with a standing window between them.** A unit that backs off whenever a melee body closes on it runs forever, the melee class never lands a blow, and every match becomes a chase (measured: match length roughly doubled). Give the step-back a duration and a cooldown of standing and shooting; keep *wounded* retreat sustained; and keep a no-hit timer that overrides every style, which is what stops two ranged units circling each other for a whole match.
- **A long-reach unit holds its band at a fraction of its reach, so a "can I close?" window measured against a constant never opens.** Ranged units stand off at about 90% of their own reach, so a gap-closer gate written as `step + 16` (240 px) sat *inside* the 247 px a long rifle holds: the one move every kit owns for crossing open ground could never be spent on the one enemy it was written for (the blinkless unit ran three 200 s fights without landing a hit). Measure the window to the attacker's own strike reach — `step + ownRange` (272 px for a fist), which is the quantity that decides whether the step lands *in swing* rather than on the target's head. Measured effect: +31% melee swings and -17% time spent fighting alone over 24 seeded battles with the win rate unmoved, because the step is on a 30 s clock and the band re-anchors with every shot — a behaviour-only change is not a balance win, so say which one you got.
- **A proximity-panic radius must never exceed the band it belongs to.** Clamp it to about 1.6x the unit's own stand-off band, or a short-reach unit carrying one long move flees from the fight it came to have.
- **A band derived from the unit's longest move is only for units that are already ranged.** A melee unit with a lob will hold at move range with a useless fist: the two units in that shape sat at the bottom of the board (8% and 29% wins) until their band went back to their own reach.
- **Bodies, walls and targets: a point-sampled clear line is not body clearance.** A clear straight line holds true while the body's own shoulders still catch the corner, and a path search asked about a *solid* goal tile (an enemy knocked into a wall) returns nothing, so the body leans on the stone. Snap the goal to the nearest open tile, escalate to the path search the moment a walking body is blocked, sidestep toward the side that is actually open rather than a coin flip, and give anyone standing inside geometry an escape. Watch blocked time per body and read the **worst** case, not the mean — that is where the snag is.
- **A collision test that demands a fully clear destination freezes a body already inside geometry — permanently.** A knock, a pull or a dash shoves a body into the wall, its collision corners end up in stone, and a per-axis `!solid(destination)` test then refuses *every* direction, including the ones that would free it. It stands frozen for the rest of the match, which is exactly what "the units get caught on the obstacles" describes. Judge a move by penetration instead: count how many corners are in stone before and after and allow the move when it does not make the overlap worse. An embedded body can then always push its way out, and the escape/path logic above has something to work with. Measured: mean stuck time per body 0.66 s -> 0.06 s.
- **Cap crowd separation below the slowest walker's speed.** Separation is applied as a force added to the walk vector; with several allies crowded around one slow body the sum exceeds that body's walking speed and it stands pinned by its own team for a minute — 63 s of "blocked" time in the measured ladder belonged to a body that was never near a rock. Clamp the separation contribution to a fraction (~0.45) of that body's own walk speed: a nudge, never a wall.
- **Hold the pathing decision for a window; a test re-evaluated every tick makes bodies walk on the spot.** With a straight-line/line-of-sight test as the gate on the path search, an enemy stepping in and out of cover flips it every few ticks, so the heading alternates between the direct line and the path around the rock and net displacement is zero. Keep the current choice for ~0.5 s after the last blocked sample before re-deciding.
- **A leash measured from the team centroid degenerates for a lone unit, and a return-to-the-centroid is a scrum.** With no allies left, "home" is the unit's own spawn point, so a leashed unit dutifully walks home forever and the match runs to the floor timer with nobody fighting. Gate the leash on having at least one living ally, and send a straying unit to the *edge* of its line (the ring point on its own bearing) rather than the centroid, or every leashed unit piles onto the same tile.
- **A destination must be a real destination.** A retreat point computed as `self + away * distance` lands outside the map when the body is already backed against the border, and a path search has nothing to say about a tile past the wall. Clamp retreat points inside the arena; if the clamped point is closer than a step, that is "nowhere to run" — which must mean **turn and fight**, not stand still (a wounded unit holding at 300 px from its target does nothing at all). Give the goal one guard for this (`distance-to-goal < ~14 px` -> drop it, or aim it at the enemy if the body was fleeing), and clear the slide timer when escaping stone so the wall-slide cannot rotate the escape heading a quarter turn into the neighbouring wall.
- **The stuck metric must be the complaint, not a proxy.** A raw "time wanting to move but not moving" counter also counts bodies cornered and killed while retreating, bodies waiting inside their own crowd, and holders strafing into a wall — three legitimate states, and a check that flags them cannot be made green by fixing anything. Define it as the player would: the body *has somewhere to be* AND is *pressed on stone* AND its net displacement over a sampling window (2 s) is under a body-width. Log the per-body average and the worst single run separately — the average is the fix's score, the worst run is the next finding.
- **Validate a probe's own field reads before believing a probe finding.** A diagnostic that reads a field the engine never writes gets `undefined`/null and reports "no target / no goal everywhere", and a truthiness test on a tile value (tiles held the strings `"wall"` / `"floor"`) reads *every* tile as solid — two confident, wrong conclusions in a row, each sending the fix after a mechanism that did not exist. Read through the engine's own accessor (`lv.tiles[y][x] === "wall"`), log one raw sample plus its type first, and cross-check any "every one of them is X" result against a state you can see another way. **Check the shape of the collection, not only the field name** — a roster list of move *keys* iterated as move *objects* has `mv.st` undefined on every entry, and a filter built on it reports a confident absence ("no unit in the game owns a gap-closer") that reached a shipped document before a positive control on one known-good entry disproved it.
- **Verify a style with counters aggregated per style, from spawned bodies excluded.** Per-body numbers — mean distance it fights at, time inside melee range, health retreats, recoil episodes, share of picks onto the enemy with the least health, blocked time, distance while badly hurt versus healthy — turn "they feel different" into assertions. Summoned/token bodies inherit a default style and will outnumber the real units in that bucket, which makes a healthy style read as broken. Run the same scenario before and after and say what the measurement does not cover.
- **An opening layer that owns the first seconds must hand the body back, and it must walk its own bodies.** A formations/pre-stage layer answers the planner's first question (a hook returning a plan or null), sets each unit's shape, post, claim and wave, then releases after N seconds or the first death so the unit's own style fights the rest of the match. Two traps: the planner will not move a body that has nothing in reach, so the layer walks its own units to their posts; and a coverage assert must exclude units created *after* the plan (summons, revives) or it reports arithmetic as a defect. Depth: `references/combat-ai-movement-and-metrics.md`.
- **A measurement tool's loader list is part of its correctness: it must load every module the game ships.** A new layer was missing from the loader list of all three tools at once — the headless gate, the balance ladder and the behaviour report — and each went on printing confident numbers for a build that does not exist, in the same session, three times. Make the gate assert the module is loaded (`must("the harness is measuring the shipped game", !!win.<MODULE>, …)`) and have the report tools warn. A missing loader leaves no trace in the output, which is exactly what makes it worse than no tool at all.
- **A gate must measure the same fight twice; a sampler must not.** A gate that draws its teams with the sim's own `Math.random` gave identical code a threshold FAIL and then a PASS on the next run: a coin flip inside a test, worth less than no test. Seed the context's RNG before the modules load (`--seed=N` to sample another field) and leave the balance/sampling tools random on purpose — those exist to sample, the gate exists to gate. Prove determinism by reading the same figure on two runs, and keep the gate inside one tool call: choose the sample per section, let a structural assertion ride a smaller one (posts, claims, geometry, a timed release all hold on half the battles; a clocked mean does not), and never background the run, which exits without its pipeline output.
- **Measure a style in the units its doctrine is written in.** A style table states its stand-off as a fraction of each unit's own reach, so a census of raw pixels against fixed thresholds (62 px "close", 150 px "far") measures the unit's REACH and calls it its STYLE — a long gun is scored as backing off for standing exactly where its doctrine told it to, and no two styles are comparable. Report the ratio, and read the target distance off the value the engine actually aimed at (stash the band where the movement code computes it) rather than recomputing a second opinion in another file, which measures a different number.
- **A threshold that a deliberate design change moved is re-derived from its claim, never loosened to pass.** A flat "the killers pick their own target 25% of the time" floor predated a layer that deliberately makes teams more disciplined; the claim it actually makes is a *ratio* (killers behave differently from the marching line) and that held at 2.4x. Restate the ratio, set the floor to what the claim needs, and put the reason in the assert message. Silently bending the number, and leaving a stale floor in place to flap, are both wrong.
- **Intercept, don't chase — and never let a blink into the aim point.** Walking at where a target *stands* is a step behind it forever. Give every unit a velocity measured from its own last two positions rather than reported by each mover, so walking, strafing, knock-backs and dashes are all covered; then aim where the target WILL be whenever the unit is outside its own swing. Two guards: a unit already in swing never leads (or a knife fight becomes two bodies orbiting), and clamp the lead OFFSET in length, or one teleported frame flings the aim point off the map.
- **Size the sample before claiming a move, and treat two identical runs as the noise floor.** A +0.9 point duel difference at 108 fights meant nothing — the same change measured flat at 216. Two runs of one IDENTICAL balance build disagreed by up to 18 points on a single unit, so a printed ±12 interval understates the real floor and only the tails resolve. Report overlapping intervals instead of a point estimate.
- **A duty/plan layer that returns an OPTIONAL destination must state what "no destination" means, and the safe meaning is "walk to your band" — never "stand still".** Getting that default wrong is the most expensive bug in a tasking layer: every unit holds from the first tick, no team ever closes, and every match runs to the time limit with the floor deciding the winner. It passes every structural assert (no NaN, nobody out of bounds, every move fires) because the units are visibly doing something. The tell is in the lengths: **per-mode MEDIAN match duration sitting exactly on the ring/round clock**, plus one side with zero damage in a slice of matches (measured: median 96.7 s in all four modes and `no-damage=36/90`, versus a 43 s median once fixed). After any change to a movement or duty decision, read the medians and the no-damage count, not just PASS/FAIL.
- **Counter that whole class with a global silence clock, not with another retreat rule.** Stamp the moment blood was last drawn anywhere on the field (one line where hp is deducted): when nothing has been damaged for ~12 s, void *every* plan and press, and make it outrank withdraw, leash and hold — each of those is right on its own and their sum is the fight that never starts. That is the cure for the diagnosis above (a match ending with no damage dealt by either side and nobody down, about 1 battle in 90). Verify it as a count over 90+ matches (zero such battles) and watch the structural harness's own no-damage assertion, which read 0 afterwards where it had been failing two runs in four.
- **Cooperation is a per-team called target plus per-unit doctrine, and the call must be a doctrine, not a leash.** Keep one team clock that names a target (wounded first, then the menders, then the long guns — sticky, so the team does not dither between calls), then let each style deviate to its own `prefer` — but only inside reach of the line (refuse a private target further than the squad's call plus about a screen). Measure it: the share of attacks landing on the called target should read ~50-100% per style. 0% means the call is ignored and the team is fighting five private duels; 100% means the call has become a leash that erases every style's identity.
- **Gate "break contact" on the team's exchange, not on local arithmetic, or both sides disengage at once.** The same retreat rule firing on both units in a 1v1 turns a winnable fight into two bodies jogging at opposite walls until the floor kills them. Require all three: not the last unit standing, the enemy is not in worse shape, and the team's total-health tilt is negative — a real exchange measure, because five units on 10 health are not winning. Add a cooldown after regrouping or the line oscillates between "regroup" and "press" for the whole match (measured: 67k regroup tasks across 200 fights, 756 after gating).
- **A support unit's contribution needs a counter that excludes self-buffs, and the behaviour must engage for every unit that carries the move.** Count mending that lands on *somebody else* separately from total healing (increment only when caster !== target) — self-heals otherwise count as party support and "some of these units heal the team" becomes unverifiable. Make the aid task fire for any unit carrying an ally-aimed move, not only the units whose style is literally named healer, or a commander or a smith with a mending move never casts it.
- **Give the arena a variety set and assert it; when the design changes, re-band the openness assert instead of deleting it.** Several authored layouts per environment, plus colour schemes, should each appear across a few hundred matches (assert all of them were built). When an obstacle pass cuts the floor to 80%+ open, move the assertion band with the design — the band is what stops the next edit quietly rebuilding a maze.
- **After landing AI behaviour, re-run the whole ladder and re-tune the systemic levers before touching a unit.** Behaviour moves balance with no unit number edited — see the earlier rule about the levers the checker prints.
- **Fix the measure before touching a unit's numbers.** An assertion that cannot physically separate two classes fails by a hair forever: "the killers go for the wounded and the duelists do not" read 73% vs 69% because the squad's called target *is* usually the most-wounded body, so every style scored alike — the design difference is that a killer *leaves* the call. Measure the off-call share (`1 - onCallShare`) instead: knives 34%, the marching styles 12%. A metric that only re-measures the team call is how a session gets spent tuning kits for a measurement bug.
- **A support unit topping the ladder means too few units can answer it, not that its numbers are too high.** Healing had one counter, carried by five kits, so a mender facing a team with no counter-carrier was unbeatable (measured 100% wins in a 90-battle slice). Widen who carries the counter before trimming the heal: a counter concentrated in a handful of kits is a free hand for the rest of the board.
- **Commentary and personality are an event stream, and must not draw from the sim's own randomness.** The sim emits scene events (who died, to whom, who was held, who was saved); the presentation layer only turns them into words, and every announcer line must have an event behind it — a whitelist of the sim's emit sites is the assert that catches the rest. Randomise the *words* only: a talker or timer chosen with the sim's `Math.random` stream moves every later crit and dodge roll, so identical seeds stop producing identical fights and the balance numbers drift for no reason.

- **A blow that deals nothing must say so on screen, and the match must count it.** A damage funnel has several ways to return zero, and any of them that prints nothing renders as an attack that passed through the body — the report comes back as "the basic attack does nothing", which is indistinguishable from a display bug and is usually both at once. Label every zero path in the funnel (miss on a veil/accuracy roll, `block` when armour eats the blow *including weak hits that never reached the damage floor*, `ward` when a shield absorbs the remainder, `miss` for an aimed shot that expires having landed on nobody), and keep per-match telemetry counters (swings, shots fired, blocked, warded, arrived-at-nothing) so the rates are numbers. Two traps when editing that code: a damage-over-time tick calls the funnel with a **null attacker** and is silent by design, so guard any new text/colour call on `src` and leave tick hits quiet; and adding an early return must preserve the funnel's own arithmetic — cutting at `<= 0.5` where rounding a 0.5 remainder had always dealt 1 is a real sim change, and the structural harness is what caught it.
- **A defensive mechanic that absorbs whole blows and is sized off the defender's own pool is a wall, not a shield.** `shd = max * aegis` spent as `min(shd, dmg)` scales hardest onto the tankiest bodies and nullifies every small hit, so the fight has no feedback until the pool empties — reported as "X is unkillable", invisible to a win-rate ladder (the wall kits read mid-table), and found by instrumentation instead. Convert it to a **share** (`absorbed = min(shd, dmg * share)`) so every blow leaves a mark; the pool is spent at the same rate per point, so the ward's *total* protection is unchanged and only the number of blows it is spread across goes up. To hold the protection constant the pool grows by `1/share`; to nerf it, leave the pool. Then trim the largest plate, restore any body the mechanic pushed down with survivability rather than a bigger plate, and quote absorbed-versus-through numbers rather than a win rate the sample cannot resolve.
- **Separate activity from behaviour from outcome, and judge a change by the middle one.** Census the reason string on every decision (seconds spent in each: `baiting the shot 1844s`, `taking the reload 6640s`) — that is the only evidence a tactic fired at all rather than being written. Then: a change that moves only *activity* (decision-seconds) is a revert — approach-discipline variants that changed thousands of decision-seconds left the win rate at 34.0% / 33.3% / 30.6% on the same controlled fight set. A change that moves a *behaviour* metric (time to contact, seconds spent closing on a loaded gun, stuck time) is a keep as a correctness fix, and must never be described as a balance gain: the intercept (aim where the target will be, not where it stands) left 216 duel win rates flat at 35.6% vs 36.6%, both intervals 30-43, while cutting shots met at a loaded gun 15% -> 12% and gunwalk 48 s -> 39 s, the same way in two independent samples. Quote the metric that moved and the one that did not. The honest root cause is often not behavioural at all: a short-reach body against a long-reach one loses to reach, and no amount of leading fixes it.
- **When the sim owns the RNG, a before/after needs both builds loaded side by side.** Two runs of one build differ, so a sequential A/B measures noise: load the committed file (`git show HEAD:<path>`) and the working tree into two contexts in one process, or seed the scenario's own draws (teams, spawns) so both arms see the same fights. Quote per-body rates, not raw counts.

## Tuning difficulty and pacing
- Put every dial in ONE named table (XP requirement, spawn cadence, kill value, wave slope) with a comment stating what the *product* of the dials does. Balance that lives in scattered literals cannot be tuned.
- Scale difficulty inside a shared helper that every mode calls. A per-mode copy drifts within one edit; an inline `mode === "x" ? … : …` in a gameplay rule is the smell.
- **Every ceiling constant is its own site, and each mode may still hold one.** A ramp requested for two modes by name landed in one while the other kept a flat cap — and that flat cap existed in *two* paths (the spawner pulse and the split/divide path), so banding only the obvious one left the mode off the ramp twice over. Grep the number, not the mode name (`grep -n "capNow\|surviveCap\|<cap value>"`), band every site, and **assert each mode's band separately in the checker** — a single mode-scoped assert stays green while its sibling drifts, so one green suite proves nothing about the other mode.
- When a requested change pulls both ways — more XP per kill *and* slower levelling — the stated **outcome** wins: move each dial its own way (level cost up, spawn rate down, kill value nudged up), keep the net effect in the comment, and report the net effect plus the dial names so it stays a one-line change.
- Longer runs come mostly from spawn cadence, not XP maths. When runs ramp too fast, cut the tide first.
- Fractional XP: a level-up loop comparing `xp >= need` is fine, HUD readouts are not — floor them (`xp | 0`) the moment kill values stop being whole numbers, and check any derived bar width too.
- **A slow ramp is a gentle *climb* from a busy opening, not a quiet opening.** Build one curve function with an explicit knee in seconds and make *every* cadence path read it — wave pulses, hordes, secondary spawners such as nexus/generator pulses, and the population ceiling; the one spawner left on the old flat dial is exactly where the pacing leaks. Make the curve's **floor** its own dial and keep it near full rate: a floor at ~0.3x of full behind a small ceiling reads as an empty hall and draws "too boring" however steep the climb after the knee. Flatten the pre-knee slope instead, and hold the post-knee absolute slope identical so the late balance the user already approved does not move.
- **The population cap has a *base* dial as well as a growth dial, and the base is what sets minute one.** A ceiling that grows correctly still starves the opening if its base is tiny — "no more than 14 foes alive" reads as empty ground at any cadence, while the same curve with a base near 26 reads as a crowd before the knee.
- **Prove a distance dial against the model, not against the label.** Measured behaviour beats the readout: a yardage/aim control each need at least one sampled assertion (see `references/course-shot-and-aim-verification.md`), because a stated distance quietly divided by surface friction, or a marker that snaps behind the player at an elbow, both render as plausible numbers in the HUD.
- **The curve's clock must come from the mode's own clock:** run time in endless/survival, a per-level clock reset on level load in authored modes. Probing a time-based dial against the wrong clock (a global run timer in a mode that reads per-level time) reports "no change" and looks like a dead curve — set the clock the mode actually reads, or measure by wall-clock observation instead.
- **A second complaint about the same dial means the first needed a curve.** When the user says pacing is still too fast after a multiplier change, shape it (quiet early, steeper late); another multiplier will not satisfy them. Expect the shaped version to draw the opposite complaint next ("boring at the start") — that is the floor talking, not the shape: raise the floor and the cap's base, do not revert the curve.
- **A run has to be losable: escalate on an unbounded curve, not a plateau.** Two plateaus make late runs immortal — enemy health/damage growing only linearly while a drafted build grows multiplicatively, and a population cap that saturates (`min(380, …)` stops mattering minutes in). The dominant lever is **contact damage**, not health: more health only makes sponges, whereas nothing outlasts a damage multiplier that keeps climbing (~1x at the knee, ~3x five minutes later, ~15x fifteen minutes later). Apply that one unbounded multiplier to damage, health, density and the cap, and read the mode's own clock so lingering anywhere is punished.
- **Acceptance test for losability: arm the player, idle, watch the health bar.** Sample health over ~10 s early (a scratch) and late (lethal — a full pool gone in a couple of seconds, the run closing and the score committing). A player still untouched after a minute at fifteen minutes means the run cannot end; that is a bug, not a balance opinion.
- **Check the damage window's own logic before blaming the curve.** A hit window that is *re-armed* by a laxer test than the one that *gates* damage (gate at `t <= 0`, re-arm whenever `t <= 0.12`) is permanent immunity: with one foe touching, the timer bounces inside the lax band and the gate never fires — an effectively unkillable player with any horde on them. Use one threshold for both the gate and the reset, and assert the immunity branch is gone.
- **Elite/boss layers need their own clock and must spawn *past* the population cap.** A random named-boss roster (first one at a time mark, then more and faster) does nothing through the cap — it is throttled to zero in a saturated field. Scale their health on the same unbounded curve and escalate the count and the interval with minutes past the mark; punish **stacking** with a damage multiplier plus a callout and a live count in the HUD rather than with more health, so the player is forced to break the pile instead of out-tanking it.
- **A wave is a standing target, not a spawn rate, and the wave number is the minute survived.** Make one clock the run's spine (`waveOf(t) = 1 + floor(t/60)`, one wave-length dial) and let each wave *state what the field may hold* for that minute; every spawner chases that target. Inverting it — cadence first, population as a side effect — lets each run settle somewhere different, and the HUD's "wave 13" no longer means anything a player (or an assert) can hold onto.
- **A two-stage ramp keeps the frame budget honest: fodder to a hard cap first, then the ramp moves to the elite band.** Fodder per wave (~100) pins at its hard cap (~800) around wave 8; from there the same escalating slope is spent on named/boss count (+25/wave under its own cap, under an overall entity ceiling). One ramp on one band saturates the frame budget and the difficulty stops moving; two bands buy roughly twice the waves before the numbers themselves are the dial — and those caps are a performance dial the user should be told by name.
- **Level in kills, never in minutes.** Flat kill value (1), requirement a curve in level (`14 × lv^1.55`), elites worth several kills, set-pieces more again. Two players who play the same way level identically whatever the tide does, so the difficulty ramp and the level ramp cannot drift apart — minute-based XP is what lets a lucky run out-level its own spawn curve.
- **A mode's HUD must name the number that drives it.** A wave pill in a floor-based mode shows the *floor*, so the wave its difficulty rides is invisible and unverifiable from the UI: name it in that mode's clock line instead of trusting the pill.
- **A new layer's timer must be initialised to its own mark, not 0.** Roster/elite/count/"already warned" state left at 0 fires the first elite at t=0; seed the timer with the mark and clear all of it in the run/level loader (per-level layers reset with the level clock), then verify the silence before the mark and the arrival at it.
- **Gate the top tiers of the reward pool (legendary/rare) behind run progress — level count or passing the knee — so the first draft is never a jackpot.
- **Reward variety is a tuning tool, not just content.** Flatten tier weights so mid tiers dominate, damp the weight of anything already stacked (`base / (1 + stacks × k)`), and guarantee one slot the player has never taken. Then make every card's stat *real*: a card that displays a stat nobody applies is the fastest way to make a whole draft feel fake.
- **Unlock-everything requests:** keep the unlock numbers in the data as lore/ordering and flip the gate to an always-true accessor (`heroOpen(id)`) rather than deleting the field — the roster loop then has one place to read, and re-gating later is one edit.
- **A game that advances the simulation one tick per rendered frame has no pacing, only a frame rate.** The authored duration becomes wall-clock fiction (a sequence the event table authors at ~2.6 s takes 19 s at 15 fps) and every machine plays it at its own speed. Accumulate real time and step a fixed tick table (`acc += dt; while (acc >= TICK) { step(); acc -= TICK; }`), and answer "too slow to watch" with a persisted speed multiplier (x1/x2/x4 on a key plus a control) rather than with skip-only — a player reaching for skip is telling you the default speed is wrong.
- **The other half of "the game feels slow" is the renderer, not the dials.** A static scene rebuilt every frame — a full visibility scan, then a per-tile gradient, `clip()` and texture fill — spends the frame budget on a world that changes only when the world changes. Paint it once into an offscreen canvas and blit per frame, keep entities/auras/fx/cursor live on top, and invalidate on fog reveal, reclaimed ground, a texture load, a new map **or a map-size change**; key any cached visible-tile list on map size and seed as well as the camera, or a new island reuses a stale index and renders blank tiles.
- **Measure the frame budget before arguing about a dial, and report the number.** A rAF counter per phase before/after, plus a canvas pixel-sample delta to prove the layer actually repainted — a cache that went stale shows a delta near zero where change is expected. Probes and the scripted-play harness: `references/pacing-measurement-probes.md`.

## A mode that removes a resource
- **Hand the mode the slot; never paint a second one.** When a mode zeroes a currency, the default panel keeps rendering every frame underneath it, so the mode's own row lands beside a full set of dead controls. Hide the default panel, re-point its heading and sub-label, and paint the mode's rows in that slot — one set of controls per screen — then assert the removal by count, not by looking at a screenshot.
- **`hidden` loses to `display:flex`.** A row class with an explicit display overrides the attribute; add a `[hidden]{display:none!important}` rule at the end of the sheet and check `getComputedStyle(el).display`.
- **Grep the currency, not the button.** Every surviving hit in the game module needs a mode gate or a mode-neutral rewrite: payout tags on the marks/goals list, credit call sites and refunds, "Buy …" labels and empty-state copy, log lines, flavour paragraphs. **A payout printed but never credited is worse than a missing feature** — the player reads a number the code never adds.
- **Audit the automation's affordability gates.** An auto-keeper/auto-buy path gated on the currency silently no-ops in a money-free mode and reads as a broken feature. Decide per gate — free in the mode, or deliberately skipped — then force the trigger (set its timer to 0) and read the state a frame later to prove it acts.
- **The welcome/log line is written before the mode flag exists.** A shared loader announces the default mode; rewrite that line in the mode's own apply step, guarded so re-entry cannot mangle another line.
- **Re-verify the untouched mode in the same pass.** A mode-scoped change is done only when the default mode still shows its own panels, prices and payouts — drive both from the menu and read both the state and the DOM.

## Standing rules
- One mode or feature at a time, and report what a verification actually proved separately from what is still unverified.
- Stage changes locally, verify, then **commit** — a clean tree is the deliverable, and "everything committed" means the whole tree, so inspect and *resolve* unrelated uncommitted work you find rather than leaving it loose — commit it when it is a real change, and back it up then revert it when it is incidental churn. A lockfile rewritten by a package install is the common case: compare the manifest against both the working and the `HEAD` lock, diff the resolved versions, and if nothing moved (entries only relocated between the top level and nested `node_modules/`) it is layout only — back it up to the temp dir, `git checkout --` it, and say so in one line. Stage the game's own directory (`git add -A games/<slug>`), never `-A` at the repo root, so unrelated dirt cannot ride along in your commit — but note that a directory-scoped `-A` also stages the throwaway probes (`tools/_*.js`, the house marker for a scratch file). Untrack one with `git rm --cached <file>` and commit **without** `-A`/`-a`: a directory `add` re-stages the file you just untracked, so the commit reports "nothing to commit" while it is still in the index. The durable fix is a `games/<slug>/.gitignore` carrying `tools/_*.js`. Never push to a public repo or deploy without an explicit ask; state in one line that it is committed and waiting. Bump cache-busting version strings for any asset a returning player has already cached, and re-load through a fresh query buster while verifying — a check on the plain URL runs the previous script, so an old build looks like a failed fix; confirm the served document names the new version before calling the change live. Bump that string **after** the last edit to the file it covers — a bump taken before a further edit leaves the browser replaying the pre-edit script under a version that looks current, so the verification ran code you had already replaced.
- **A scripted identifier rename must not touch property accesses, and a new block must not reuse a name already in the file's scope.** Replacing `\bname\b` in a source file also rewrote a method call (`.tasks()` became `.bxtasks()`) and the same word inside a message string; a syntax check cannot see either, so it survives to runtime as a TypeError. Restrict the rename to declaration sites (or skip matches preceded by a dot), then grep the file for `.<newtoken>` to prove no property read moved, and re-run the tool. Likewise, an assertion or debug block added to a large single-scope file must prefix its own identifiers — a duplicate `const name` is a load-time SyntaxError that reads as "the harness is broken".
- **Verify a rebuilt source file parses before overwriting it, and re-read a file that was reverted.** Build the new text in memory, write it to a temp path, `node --check` *that*, and only then write the real file: a block inserted beside a `/* ... */` comment can split the comment and ship a SyntaxError in a heavily-commented file, and `git checkout -- <file>` is the recovery. A revert also restores the original prose, so an anchor copied from an earlier edit of that same file silently matches nothing — re-read the file, or anchor by regex on the stable code line, instead of reusing a literal you wrote an hour ago. `assert count == 1` is what tells you which happened.
- **Make exact-string edits CRLF-proof.** A Windows checkout is CRLF on disk, so a search/replace built from LF text matches nothing and writes nothing while the tool still reports success. Read with `newline=""`, normalize both sides, and assert exactly one match before writing — a silent no-op edit reads later as "the fix did not work".
- **A rejected `git push` means another author pushed first: rebase, never force.** Read what arrived and what it touched (`git fetch origin`; `git log --oneline HEAD..origin/main`; `git diff --name-only HEAD...origin/main`), then `git pull --rebase origin main` and finish with `GIT_EDITOR=true git rebase --continue`. The recurring conflict is the `index.html` cache-bust block, because a second session bumped the same `?v=` lines: each side of the conflict is the old and new copy of one line, so take the HIGHEST version per asset (the other author's is usually newer for files you did not touch). Never force-push and never `reset --hard` once your work is committed — the other session's commits are the site's live state, and a rebase keeps both histories.
- When one mode is the reference implementation, generalise it through shared helpers rather than copying it into the other modes; parity across modes is a standing requirement, not a per-request one.

# 2D Game Building

## Before art

- Lock a **logical resolution** (e.g. 320×180, 640×360, 1280×720) and a scale policy.
- Choose **pixel** or **HD vector**; do not mix without a rule.
- Decide camera: fixed, follow, room-based, or scroll.
- Define the tile grid and collision units in the same coordinate system.

## Rendering budget

- One sprite atlas, power-of-two pages, max 2048 on low-end.
- No per-frame `new Image`, canvas resize, or string-built draw calls.
- Batch by texture; avoid alternating materials.
- Use a single camera transform; do not fight the engine with per-sprite scaling.
- Pixel art: nearest filtering, no rotation, integer camera positions.

## Animation

- 8–12 fps for pixel characters; 24–30 fps for HD vector.
- Every action needs: wind-up, active, recovery.
- Use hit-stop and a flash/squash for impact; do not rely on particles alone.
- Keep a **frame budget per character** and a max simultaneous animated actors.

## Input and feel

- Keyboard + pointer + touch; remap to one action map.
- Coyote time and input buffering for platformers.
- Deadzone and aim assist for twin-stick.
- Test A/D and left/right signs in code and on screen; see the `controls` checklist.

## Level and UI

- Tilemap + object layer + collision layer, not one giant image.
- Parallax layers at 2–4 depths; cheap and readable.
- HUD at a separate scale from the world; test at 1280×720 and phone width.
- Pause, mute, restart and fullscreen are release requirements, not polish.

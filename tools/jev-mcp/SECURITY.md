# Security

Never submit API keys, tokens, private prompts, personal config, or environment dumps in issues or pull requests. For a suspected vulnerability, send a minimal sanitized report using the repository's private vulnerability reporting channel if available; otherwise contact the maintainer through their public GitHub profile. Do not include a working secret in any report.

The adapter trusts its local operator. It sends supplied decision inputs to TypeSafe and may consume paid API quota. Keep keys in the server environment or a credential-manager launcher. Do not put them in URLs, tool arguments, git history, client-visible headers, or logs. Rotate an exposed credential at the provider immediately.

Stdio uses the host's local process boundary. Optional HTTP binds only to loopback and requires a separate random bearer token. It is intended for trusted local clients, has no OAuth authorization server, and must not be exposed directly to the internet. The local concurrency and payload limits do not replace public deployment controls.

Errors are deliberately generic. For debugging, reproduce with synthetic data and mocked responses rather than enabling request/credential dumps. Dependencies are locked and install scripts are unnecessary. Review lockfile updates and run the full tests before upgrading.

No process is installed as a persistent service, no firewall settings are changed, and no credential is generated by the application.
